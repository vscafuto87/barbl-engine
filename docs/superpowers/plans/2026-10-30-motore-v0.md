# barbl-engine v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un motore in Dart puro che genera da un profilo un piano conforme al contratto usando solo la KB, con il caso d'oro 01 verde in CI.

**Architecture:** `kb/` (ex barbl-kb) contiene i dati YAML; `bundle` li trasforma in un unico JSON; `generatePlan(profile, kb)` è una funzione pura che applica sei passi (template, esercizi, prescrizione, carichi, parametri e motivazioni, controlli) e restituisce `Generated`, `NotCovered` o `InvalidProfile`. Il motore ha modelli interni propri e parla con l'app solo in JSON del contratto.

**Tech Stack:** Dart (SDK stable, `^3.13.5` come l'app), `package:yaml` (solo nel codice di `bundle`), `test`, `lints`, `json_schema` (solo nei test e in `eval`); Python 3.12 con `pyyaml` e `jsonschema` per il validatore della KB.

**Spec:** `docs/superpowers/specs/2026-10-30-motore-v0-design.md`

## Global Constraints

- Nessun numero di dominio nel codice Dart: serie, ripetizioni, recuperi, RIR, soglie e tempi vengono solo dalla KB. Le costanti ammesse sono quelle di formato (`bundleFormat = 1`, `schemaVersion` del contratto `"2.0"`, `"1.0"` del profilo).
- `generatePlan` è pura e deterministica: niente orologio, casualità o I/O; non lancia per un profilo.
- `lib/` fuori da `lib/src/bundle/` non importa `package:yaml`, `dart:io` né `package:json_schema` (lo verifica `test/architecture/imports_test.dart`).
- Identificativi in inglese, uguali al contratto; testi per l'utente in italiano e inglese dalla KB.
- Mai il testo delle fonti nella KB; PDF, Markdown estratti e dati strutturati dei programmi non entrano nel repository.
- Mai commit diretti su `main`: ogni lavoro su un ramo, PR approvata da Vincenzo, nessun merge da soli. Commit e testi in italiano; i commit finiscono con le righe di attribuzione richieste dalla sessione.
- Prima di dichiarare finito: CI verde (`validate-kb` e `engine`). In questo ambiente l'SDK di Dart non si scarica: la verifica dei task Dart è la CI della PR (`gh api repos/vscafuto87/barbl-engine/commits/<sha>/check-runs`), che si legge dopo ogni `git push`.
- Le versioni dei pacchetti Dart non si possono verificare offline: se `dart pub get` fallisce in CI, si corregge il vincolo nel `pubspec.yaml` e si rilancia.

## Review Focus

- `knownLoads` con `kg` ≤ 0, non finito, o con lo stesso `exerciseId` due volte → `InvalidProfile` (non un carico negativo nel piano). Test nel Task 6.
- `knownLoads` per un esercizio che il profilo non porta nel piano (es. `dumbbell_bench_press` quando la panca con bilanciere è disponibile) → ignorato, nessun errore. Test nel Task 9.
- `gym.equipment` vuoto, con duplicati o con valori sconosciuti → mai un'eccezione: vuoto o insufficiente dà `NotCovered(equipment)`, gli sconosciuti si ignorano. Test nel Task 7.
- `sessionDurationMin` uguale alla durata stimata → coperto (limite incluso); un minuto in meno → `NotCovered(duration)`. Test nel Task 8.
- Campo sconosciuto nel profilo o `schemaVersion` diverso da `"1.0"` → `InvalidProfile` (lo schema del profilo ha `additionalProperties: false`). Test nel Task 6.
